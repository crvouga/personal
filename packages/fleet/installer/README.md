The shared installer is [modules/installer.nix](../modules/installer.nix) plus [modules/installer-iso.nix](../modules/installer-iso.nix). The `Fleet` workflow builds `.#installer`, uploads a 14-day Actions artifact, and publishes the same ISO to the `fleet-installer` release so the download does not expire. A new machine runs [scripts/fleet-node.sh](../scripts/fleet-node.sh): one file, no Nix, no checkout. It fetches that release and installs `ci`, `web`, `cache`, `netboot`, or `devbox` only after the role and the internal disk are confirmed. `just build-iso` still builds it locally when a Linux builder is available. `just fetch-iso` is the legacy artifact download.

The ISO contains the `ci`, `web`, `cache`, `netboot`, and `devbox` closures and a manifest at `/fleet-install-manifest` (the live system reads `/iso/fleet-install-manifest`). It does not contain `ci-gpu` or an age key. The boot menu defaults to a role selected deliberately in the boot menu. The other entries pass `fleet.role=web`, `fleet.role=cache`, or `fleet.role=netboot`. `fleet-auto` then wipes the one internal disk `select-disk` chose and installs that closure. SSH uses [settings/installer.nix](../settings/installer.nix) and is optional. One USB boots every role on the image, from Windows, Linux, or an empty disk. The netboot ramdisk is the same installer without those closures, and `fleet-auto` exits without wiping when the manifest is absent. TODO: the netboot host does not serve this ISO. The netboot role tells other clients to boot local disk unless `reinstall.nodes` or `reinstall.roles` flags them.

Booting the installer ISO wipes the internal disk. The netboot ramdisk does not. The live image has no fleet hostname. A `reinstall.nodes` or `reinstall.roles` flag does not install a node, because this host does not serve the ISO.
