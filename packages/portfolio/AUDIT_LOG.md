# Audit log

Audits of chrisvouga.dev against the senior/staff hiring checklist (story and evidence, résumé, GitHub, accessibility, layout, performance, security, freshness, copy). Each round: build, run the automated suite, have a reviewer that has not seen the diffs audit the running production image, fix every blocker and major, and record every minor either fixed or as a justified won't-fix. The next auditor should find each obvious question already answered here.

Automated gates referenced below: `bun test src` (content rules, contrast, spelling, case-study format, résumé layout and ATS extraction, candidate-data agreement, placeholder guard), `bun run test:site` (built site in Chromium: axe in both themes, headings, landmarks, link names, tap targets, overflow at 320/390/1440, sticky bar, print, CLS, image sizes, third-party requests, budgets), `bun run test:docker` (nginx headers on every route, 404s, compression), `bun run health-check-urls` (daily in Maintenance).

## Won't-fix, with reasons

- **CI pass rate on `main` is not shown** (brief Issue 4). It measured 63.6% over the window, and the main-branch pipeline also deploys and builds installers, so the figure mixes deploy and infrastructure trouble with code review. The case study says so and proposes reporting the two separately; publishing the blended number would mislead in either direction.
- **Mobile page height 9.1k px at 390 (target 6k).** Started at 9.3k; the receipts, both stories and the tiles were added and the page still came in shorter. The stories and calendar are folded; reaching 6k would mean deleting evidence the checklist requires (A5, A7).
- **Brotli.** `nginx:alpine` ships no Brotli module; text assets are pre-compressed with gzip at build and served with `gzip_static`. Compiling a module into the image is not worth a custom nginx build for ~10% on 30 KB.
- **HSTS without `includeSubDomains; preload`.** `links.resend.chrisvouga.dev` (email click tracking) answers only over HTTP; preloading would break tracked links. Revisit if that subdomain gets TLS.
- **Lighthouse CI.** Replaced by `test:site`, which asserts the same outcomes directly (axe, no third-party requests, image dimensions, CLS, HTML and transfer budgets, font preload and `font-display`) without a second browser toolchain. LCP on simulated mobile is not measured.
- **AVIF.** Images are WebP at 1400 px (the largest, a gallery-only photo, is 170 KB; covers are under 90 KB) and lazy-loaded; AVIF would add a second derivative per image for a saving that does not change any budget.
- **Case-study GIF/WebM.** Static screenshots and an SVG diagram: a recording of a CLI-and-API product shows less than its outcome figures.
- **Server-side measurement (brief Issue 24).** Railway's container logs are ephemeral and collecting them needs a log drain, which is infrastructure and belongs in OpenTofu, not in the portfolio package. The footer states the actual policy: no cookies, no client-side tracking.
- **Manual theme toggle.** Optional in the brief; the site follows the system setting with no flash and no script.
- **`portfolio_urls` stays a PR gate** as well as the new daily check: removing it would change the gate count the site reports, and a dead link is caught before merge rather than a day later.
