# 9router on Railway

The [upstream 9router image](https://github.com/decolua/9router/blob/master/DOCKER.md), rebuilt with a narrowly scoped hosted OAuth fix, serves https://9router.chrisvouga.dev. Configure providers, combos and clients through its dashboard. This package also adds [Litestream](https://litestream.io/guides/docker/) and a startup lock.

SQLite lives at `/tmp/9router/db/data.sqlite` on the container's ephemeral filesystem. **Do not attach a Railway volume.** Litestream restores from `9router/sqlite` in the existing shared production R2 bucket before starting the app, replicates WAL every second and runs a final one-shot replication after the app closes on graceful shutdown. Only Postgres and blob storage retain durable state. Logs, certificates and other runtime files are disposable; the supported hosted workflow uses the web dashboard and provider OAuth/API connections, without local MITM tools.

The wrapper holds the shared Postgres session advisory lock `(923, 20128)` across restore, service lifetime and final replication. It creates no tables or schemas. A replacement waits for the old writer to exit before restoring, preventing independent SQLite databases from overwriting the same replica. Loss of the lock connection kills the process group immediately. Abrupt host loss can lose changes not yet uploaded; replication is asynchronous, not a zero-loss transaction log. R2 failures during restore stop startup rather than silently creating empty state. An empty replica is allowed on first launch.

Railway runs one replica, always on, with zero overlap and a 60 second drain budget. Its **deployment** healthcheck is disabled so the waiting wrapper becomes active and Railway terminates the old writer; otherwise the lock handoff would deadlock. Public inventory health checks still probe `/api/health`. Updates have a brief interruption while the new process restores. Do not enable sleeping, multiple replicas, or a deployment healthcheck without changing this protocol.

All service, DNS and secret configuration belongs to the [OpenTofu inventory](../infra/tofu/modules/inventory/inventory.tf.json). CI builds this package's Dockerfile and publishes/deploys it with the other workspace images. `DATABASE_URL`, the existing four router credentials (exposed as `INITIAL_PASSWORD`, `JWT_SECRET`, `API_KEY_SECRET`, `MACHINE_ID_SALT`) and shared `S3_*` values come from the production Vault document through OpenTofu. No new bucket or database is needed.

## Hosted provider OAuth

The pinned upstream version (`0.5.104`) constructs `http://localhost:443/callback` on an HTTPS dashboard ([upstream issue #4054](https://github.com/decolua/9router/issues/4054)). The user explicitly approved a narrow exception to the no-dependency-patches rule for hosted OAuth and requested coverage of every provider connection flow. [hosted-oauth.patch](hosted-oauth.patch) wires the tested [browser helper](oauth-browser.mjs) into the shared, Zed and GitLab modals, and adds the [Codex device adapter](codex-device.mjs) to the existing device-code/poll API. Docker verifies the source archive checksum, applies the patch without fuzz, installs the locked upstream build dependencies, and rebuilds the complete Next.js application so server/client manifests and cache hashes agree. It does not edit compiled JavaScript. Keep the image digest, source commit, archive checksum, patch and upstream lockfile aligned when upgrading; remove the patch when upstream provides an equivalent fix.

Hosted logins work as follows:

- **Claude:** Authorize in the tab that opens. Claude redirects to its registered `https://platform.claude.com/oauth/code/callback` page. Copy its displayed code (including `#state` when present), return to the open Connect dialog, paste it into Step 2, and click **Connect**. Full callback URLs are also accepted.
- **Codex:** Open the displayed OpenAI verification page and enter the one-time code shown in the Connect dialog. The dashboard polls for approval and saves the connection automatically, without a localhost redirect. Device login must be enabled in ChatGPT security settings or workspace permissions ([OpenAI authentication guide](https://learn.chatgpt.com/docs/auth#login-on-headless-devices)). If unavailable, the error offers **Use callback URL instead**: authorize, copy the entire final localhost URL even if it cannot connect, then paste it into the original dialog and click **Connect**. The fallback preserves Codex's registered callback, original PKCE verifier and state.
- **xAI:** Authorize, then copy the entire final localhost callback URL, even if that page cannot connect. Paste it into Step 2 of the original Connect dialog and click **Connect**. A displayed code is also accepted. Its registered fixed callback address remains intact.
- **Google installed-app providers (Antigravity/Gemini CLI):** Keep a loopback callback accepted by their installed-app registration and use the same manual full-URL flow. A public dashboard hostname is not their registered callback.
- **Trae/Windsurf/Zed:** Use manual full-URL entry with their native loopback callback formats. Both the shared modal and Zed's separate modal keep the original attempt material for exchange. Hosted flows start no callback listener, register no proxy session, and do not poll a remote listener or claim to be waiting for a popup callback. Local dashboards retain their dynamic proxy flow.
- **Other generic browser callback providers (Cline, ClinePass, iFlow, GitLab, Kimchi):** Return to the dashboard's actual public origin at `/callback` using the existing popup callback mechanism. GitLab's OAuth application registration instructions show that same public callback address.
- **Device-code providers:** Complete their verification page as before.
- **Other dedicated modals:** Kiro social login already uses an explicit manual callback; Cursor imports credentials; Xiaomi MiMo uses its existing same-origin server-side login page. None depends on receiving a browser callback at Railway's localhost.

Keep the original Connect dialog open until completion. Closing or refreshing it loses the attempt's PKCE verifier; restart login if that happens or the code expires. Callback state must match the active attempt. Plain Claude codes remain bound to that attempt by PKCE. Treat callback URLs/codes as credentials and never post them in issues or logs. Local loopback dashboards retain their automatic callback behavior, including the local Codex/xAI listeners.

Setting `BASE_URL`, `NEXT_PUBLIC_BASE_URL`, or `PORT` alone cannot fix this upstream browser code. Redirecting every provider to the public hostname also fails registrations that require loopback or provider-owned callbacks. The focused regression suite covers callback selection, state validation, copied Claude codes, local behavior, trusted callback origins and the Codex device protocol. Docker also runs [integration tests](oauth-integration.test.mjs) against the patched upstream modals and API with mocked provider responses: device login and saved tokens, manual Codex fallback, all browser providers, native manual flows and local automatic login. To run those tests outside Docker, set `NINE_ROUTER_SOURCE` to a patched upstream checkout with its locked dependencies installed.

## Cutover

1. Preserve any existing local SQLite data before retiring the local process. Stop its writers and use SQLite's backup API to make a consistent backup; do not copy an active WAL database. No local state is tracked by this repository. If existing state exists, seed the Litestream prefix with that database before the first hosted launch, using the same pinned Litestream version and credentials. Never seed while Railway owns the writer lock.
2. Publish the image, then review/apply saved OpenTofu plans in the normal foundation → vault → fleet order. Foundation forgets the existing DNS record without deleting it and retires the old tunnel ingress to a 404. Fleet imports that exact record and updates it to Railway. The adopted tunnel identity and its existing credentials remain protected for later explicit decommissioning; no tunnel resource is replaced or destroyed.
3. Check `/api/health`, configure a harmless setting, redeploy, and verify that it survives restore. Run `bun run health --only services,storage,images` after deployment.

Validate runtime handoff with `bun run --filter @pkgs/9router test`, infrastructure with `bun run check:infra`, and regenerate the consumer guide with `bun run llms:sync`. Docker context is this directory; `.dockerignore` excludes local credentials and data.
