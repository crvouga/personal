# Acceptance evidence

All data used by these tests is synthetic. A fixture executing production code is
not evidence of a successful operation on a production account. No personal
credential, mailbox, vault import, password/factor change or schedule installation
was used for development validation.

| Scenario from the implementation prompt            | Evidence                                                                                                                                                                                                                                                                                 | Boundary                                                                                                                                       |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Clean-machine dependency acquisition            | `tests/bootstrap/Dockerfile`, `run.mjs`, `verify.mjs`: actual clean Ubuntu 24.04 arm64 build starts without Node/Bun; checksum-pinned mise acquires root runtimes, frozen npm tree, OS packages and Chromium                                                                             | OS package versions follow the supported distribution. macOS and other declared Linux releases are not clean-image tested here.                |
| 2. | 3. Run the authoritative current checks:

```sh
bun run --cwd packages/password-manager tc
bun run --cwd packages/password-manager lint
bun run --cwd packages/password-manager test
bun run --cwd packages/password-manager test:browser
bun run --cwd packages/password-manager test:bootstrap
bunx turbo run tc lint test build --filter=@pkgs/password-manager...
bun run check:scripts
bun run check:agents
bun run check:llms
```

The bootstrap test requires a separately supplied Docker engine; it is a test
harness dependency, not a runtime dependency or an install hook. Its context is
explicitly assembled from source/manifests and excludes `.git`, private state and
unrelated application files. The checked container verifies onboarding without
logging in to any account.
