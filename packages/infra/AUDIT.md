# Agent-first workflow audit — `crvouga/personal`

Audited 2026-11-09 against `main` @ `9aac08ba` and live GitHub state (`gh api`, read-only).
Status: **present** = meets the outcome, **partial** = exists but differs, **missing** = absent.

## Blockers found by the audit

These change the plan. They need a decision before anything is built.

1. **No merge queue on this repo.** `crvouga/personal` is owned by a _user_ account
   (`owner.type = User`). GitHub offers merge queues only on organization-owned
   repositories (`repository.tf` already says so). Getting a queue means transferring the
   repo to an organization, which moves GHCR image paths, the Vault OIDC `sub` claims
   (`repo:crvouga/personal:*`), npm provenance, the inventory `infra_repo`, the Railway
   source repos and every application repo that calls this repo's reusable workflows.
2. **Agents and the human share one identity.** Every recent PR (#227–#242) was opened,
   pushed and merged by `crvouga` via the local `gh` OAuth token. GitHub cannot tell an
   agent from the human, so "the agent never bypasses" is unenforceable until agents get
   their own identity (a GitHub App or a machine user). Creating a GitHub App cannot be
   done through OpenTofu.
3. **Agent branches are `t3/*`, not `agent/*`.** T3 Code names worktree branches `t3/<id>`.
   Identifying agent PRs by author (after fixing #2) is more reliable than by branch.
4. **"Slow checks only on `merge_group` and `main`" needs the queue.** Without a merge
   queue, slow jobs would never gate a merge; they would only report after merge on `main`.
